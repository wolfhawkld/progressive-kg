# 检索增强生成

> 在生成过程中引入检索到的外部材料，使输出同时依赖模型参数与当前检索证据的方法。

## 从查询到证据再到回答

RAG把检索器与生成器连接起来；外部材料可更新，但检索结果不自动等于可信证据。

```text
查询 → 检索候选材料 → 选择或重排 → 构造上下文 → 生成回答 → 检查证据支持
```

例如本库新增一页数学笔记后，检索系统可将它提供给生成器，而不必因此重新训练模型参数。这个收益要求索引已更新、检索能找到该页且上下文保留了关键条件。

## 原始概率形式与常见工程形式

原始RAG研究用检索文档作为潜变量。以序列级形式的有限候选近似为例：

$$p(y\mid x)\approx\sum_{z\in\mathrm{TopK}(x)}p_\eta(z\mid x)p_\theta(y\mid x,z).$$

是否在TopK集合内重归一化检索概率取决于具体定义。若教学例子直接定义候选内权重为0.7、0.3，两个文档条件下同一答案的概率分别为0.8、0.2，则混合值为0.62。

常见工程系统把多段文档拼成一个上下文，不一定显式实现上述概率边缘化，也不一定联合训练检索器。不能把所有“检索后拼接”的系统都视为原始论文算法的精确实现。

## 将错误分解后评估

应分别检查材料是否存在、是否被检索到、是否进入上下文，以及回答是否受材料支持。

- 检索召回不足与生成误读是不同错误，修复动作不同。
- 文档相似度高不保证内容正确；多个冲突来源需要保留时间与出处。
- 引用链接存在不等于引用能支持该句结论。
- 检索内容可能包含恶意指令，应用需区分外部材料与可信执行指令。
- 与微调相比，RAG主要改变可用上下文；微调主要改变参数，二者可结合。
